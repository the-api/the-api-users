Users, login, OAuth, permissions

Add production-ready user authentication to application APIs

`the-api-users` is a module for `the-api` that adds registration, password login, refresh tokens, password recovery, users CRUD, avatar upload, and OAuth provider linking. Use it as the standard identity layer across different applications.

Before you start

What the project needs

Node.js or Bun

The API can run on Node.js ESM or Bun.

`the-api` installed

The module is mounted in a `the-api` application through routings.

PostgreSQL

The `users` table and application domain tables live in Postgres.

Tables and migrations

Create `users`, then create application tables that reference `users.id`.

Install

Packages and database

Install packages

npm i the-api the-api-users the-api-roles

bun add the-api the-api-users the-api-roles

Create local database

createdb app_api

For a new project, add `migrationDir` from `the-api-users`. For an existing `users` table, also use `migrationUpdateDir` to add missing columns without recreating the table.

PostgreSQL

Quickstart

The smallest useful API with `login` and `users`

import { TheAPI, middlewares } from 'the-api';
import Roles from 'the-api-roles';
import { login, users, migrationDir } from 'the-api-users';

const roles = new Roles({
  root: ['*'],
  admin: [
    'users.get',
    'users.post',
    'users.patch',
    'users.delete',
    'users.viewEmail',
    'users.viewPhone',
    'users.viewRole',
    'users.viewLocale',
    'users.viewStatus',
    'users.viewMeta',
    'users.editProfile',
    'users.editEmail',
    'users.editPhone',
    'users.editRole',
    'users.editStatus',
    'users.editVerification',
    'users.uploadAvatar',
  ],
  registered: ['users.get'],
  owner: [
    'users.viewEmail',
    'users.viewPhone',
    'users.viewRole',
    'users.viewLocale',
    'users.viewMeta',
  ],
});

const theAPI = new TheAPI({
  roles,
  migrationDirs: [migrationDir],
  routings: [
    middlewares.logs,
    middlewares.errors,
    middlewares.email,
    middlewares.files,
    users,
    login,
  ],
});

await theAPI.up();

Request

curl -X POST "$API/login/register" \
  -H "Content-Type: application/json" \
  -d '{"email":"john@example.com","password":"secret-123"}'

Response

{
  "result": {
    "ok": true,
    "email": "john@example.com",
    "role": "unverified",
    "refresh": "refresh-token...",
    "emailConfirmationRequired": true
  },
  "error": false
}

Errors also live in `result`. Clients should branch on result.name, for example EMAIL_NOT_CONFIRMED, ACCESS_DENIED, or OAUTH_INVALID_TOKEN.

Login module

Auth endpoints

POST/login/register

Create password user.

POST/login/register/confirm

Confirm registration e-mail.

POST/login/register/resend

Send a fresh registration code.

POST/login

Password login by e-mail or login.

POST/login/refresh

Issue a fresh JWT by refresh token.

GET/login/refresh

Refresh through query string.

POST/login/forgot

Send password recovery code.

POST/login/restore

Set new password by recovery code.

PATCH/login

Edit own profile, password, e-mail, phone.

POST/login/email

Confirm e-mail change.

POST/login/phone

Confirm phone or phone change.

GET/login/me

Read current user.

GET/login/externals

List linked OAuth providers.

Do not reimplement auth routes in applications. Use this routing as the identity layer, then build domain APIs on top of `c.var.user.userId`.

Users module

Users CRUD and avatar

GET/users

List users with field visibility rules.

GET/users/:id

Read one user; owner gets owner visibility.

POST/users

Admin-style user creation with password hashing.

PATCH/users/:id

Patch allowed fields based on permissions.

DELETE/users/:id

Soft-delete and invalidate refresh token.

POST/users/:id/avatar

Upload or replace avatar.

DELETE/users/:id/avatar

Delete avatar.

Do not insert users directly from business code: `POST /users` normalizes e-mail/phone, hashes the password, and generates salt, refresh, and verification codes.

Roles

Route and field permissions

PermissionMeaning
users.get, users.post, users.patch, users.deleteRoute-level access for users CRUD.
users.viewEmail, users.viewPhone, users.viewRoleExpose private identity and role fields.
users.viewLocale, users.viewStatus, users.viewMetaExpose locale/timezone, block/delete flags, timestamps.
users.editProfile, users.editEmail, users.editPhoneAllow edits to profile, e-mail and phone fields.
users.editRole, users.editStatus, users.editVerificationAdmin-level role, status and verification changes.
users.uploadAvatarAllow avatar upload for non-owner operations.

Hidden fields never leak through users CRUD: `password`, `salt`, `refresh`, verification codes, pending e-mail/phone fields and `oauthProviders`.

External login

OAuth providers

GET/login/{service}

Redirect to provider authorization page.

POST/login/{service}

Accept provider `code`, `accessToken` or `idToken`.

DELETE/login/{service}

Unlink provider from current user.

Supported services: `apple`, `facebook`, `github`, `google`, `linkedin`, `microsoft`, `twitter`. 

AUTH_GOOGLE_CLIENT_ID=
AUTH_GOOGLE_CLIENT_SECRET=
AUTH_GOOGLE_REDIRECT_URI=
AUTH_GOOGLE_SCOPE=openid email profile

AUTH_GITHUB_CLIENT_ID=
AUTH_GITHUB_CLIENT_SECRET=
AUTH_GITHUB_REDIRECT_URI=
AUTH_GITHUB_SCOPE=read:user user:email

AUTH_APPLE_CLIENT_ID=
AUTH_APPLE_CLIENT_SECRET=
AUTH_APPLE_TEAM_ID=
AUTH_APPLE_KEY_ID=
AUTH_APPLE_PRIVATE_KEY=
AUTH_APPLE_REDIRECT_URI=

curl -i "$API/login/google"
curl -X POST "$API/login/google" \
  -H "Content-Type: application/json" \
  -d '{"code":"provider-auth-code","state":"provider-state"}'
curl -X POST "$API/login/github" \
  -H "Content-Type: application/json" \
  -d '{"accessToken":"github-access-token"}'
curl -X POST "$API/login/github" \
  -H "Authorization: Bearer $TOKEN" \
  -H "Content-Type: application/json" \
  -d '{"accessToken":"github-access-token"}'

curl -X DELETE "$API/login/github" \
  -H "Authorization: Bearer $TOKEN"
Provider access tokens are not stored. `users.oauthProviders` stores provider identity metadata, not OAuth access tokens.

Application APIs

Build domain routes on `users.id`

In domain tables, use a foreign key to `users.id`. For owner-only resources, take the owner id from JWT, not from the body.

Request

curl -X POST "$API/projects" \
  -H "Authorization: Bearer $TOKEN" \
  -H "Content-Type: application/json" \
  -d '{"title":"First project"}'

Expected response

{
  "result": {
    "id": 1,
    "ownerId": 1,
    "title": "First project",
    "status": "active"
  },
  "error": false
}
const userId = c.var.user.userId;

FAQ

Request and response examples

How do I confirm e-mail after registration?

curl -X POST "$API/login/register/confirm" \
  -H "Content-Type: application/json" \
  -d '{"email":"john@example.com","code":"123456"}'
{
  "result": {
    "id": 1,
    "email": "john@example.com",
    "role": "registered",
    "roles": ["registered"],
    "isEmailVerified": true,
    "token": "jwt...",
    "refresh": "refresh-token..."
  },
  "error": false
}

How do I log in and refresh JWT?

curl -X POST "$API/login" \
  -H "Content-Type: application/json" \
  -d '{"email":"john@example.com","password":"secret-123"}'

curl -X POST "$API/login/refresh" \
  -H "Content-Type: application/json" \
  -d '{"refresh":"refresh-token..."}'
{
  "result": {
    "id": 1,
    "email": "john@example.com",
    "role": "registered",
    "roles": ["registered"],
    "token": "jwt...",
    "refresh": "refresh-token..."
  },
  "error": false
}

How do I get the current user?

curl "$API/login/me" \
  -H "Authorization: Bearer $TOKEN"
{
  "result": {
    "id": 1,
    "email": "john@example.com",
    "phone": null,
    "fullName": "John Doe",
    "role": "registered",
    "roles": ["registered"],
    "isEmailVerified": true
  },
  "error": false
}

How do I change profile, password, e-mail, or phone?

curl -X PATCH "$API/login" \
  -H "Authorization: Bearer $TOKEN" \
  -H "Content-Type: application/json" \
  -d '{"fullName":"John Updated","locale":"uk","timezone":"Europe/Kyiv"}'
curl -X PATCH "$API/login" \
  -H "Authorization: Bearer $TOKEN" \
  -H "Content-Type: application/json" \
  -d '{"password":"secret-123","newPassword":"new-secret-456"}'
curl -X PATCH "$API/login" \
  -H "Authorization: Bearer $TOKEN" \
  -H "Content-Type: application/json" \
  -d '{"email":"john.new@example.com"}'

curl -X POST "$API/login/email" \
  -H "Authorization: Bearer $TOKEN" \
  -H "Content-Type: application/json" \
  -d '{"code":"123456"}'
curl -X PATCH "$API/login" \
  -H "Authorization: Bearer $TOKEN" \
  -H "Content-Type: application/json" \
  -d '{"phone":"+15550000001"}'

curl -X POST "$API/login/phone" \
  -H "Authorization: Bearer $TOKEN" \
  -H "Content-Type: application/json" \
  -d '{"code":"123456"}'
{
  "result": {
    "ok": true,
    "passwordChanged": false,
    "emailChangeRequested": true,
    "phoneChangeRequested": false
  },
  "error": false
}

How do I recover a password?

curl -X POST "$API/login/forgot" \
  -H "Content-Type: application/json" \
  -d '{"email":"john@example.com"}'

curl -X POST "$API/login/restore" \
  -H "Content-Type: application/json" \
  -d '{"code":"recovery-code","password":"new-secret-456"}'
{
  "result": {
    "ok": true
  },
  "error": false
}

How does an admin create, update, and delete users?

curl -X POST "$API/users" \
  -H "Authorization: Bearer $ADMIN_TOKEN" \
  -H "Content-Type: application/json" \
  -d '{"email":"user-1@example.com","password":"pass-1","fullName":"User One"}'

curl -X PATCH "$API/users/2" \
  -H "Authorization: Bearer $ADMIN_TOKEN" \
  -H "Content-Type: application/json" \
  -d '{"email":"user-1-updated@example.com","isEmailVerified":false}'

curl -X DELETE "$API/users/2" \
  -H "Authorization: Bearer $ADMIN_TOKEN"
{
  "result": {
    "id": 2,
    "email": "user-1@example.com",
    "fullName": "User One",
    "role": "unverified",
    "isEmailVerified": false
  },
  "error": false
}

How do I upload an avatar?

curl -X POST "$API/users/1/avatar" \
  -H "Authorization: Bearer $TOKEN" \
  -F "avatar=@avatar.png"
{
  "result": {
    "id": 1,
    "avatar": "users/1/avatar/file-name.png"
  },
  "error": false
}

How do I list and unlink OAuth providers?

curl "$API/login/externals" \
  -H "Authorization: Bearer $TOKEN"

curl -X DELETE "$API/login/github" \
